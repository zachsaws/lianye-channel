# 联野 V2.1｜设计规范与中文叙事

版本：2026-10-18。独立预览，未经品牌审美验收，不是生产发布稿。

## 这一轮解决什么

01从“内容创作、场景经营、专业社群、体验节点”改为销售路径与合作形式两层。路径回答去哪里遇到买家：零售门店、内容推荐、社群私域。形式回答双方怎样合作：陈列、预约、快闪、实测、直播、试用等。企业、机构、集成与专业分销保留为可展开的其他通路，不挤进三条主要路径，也不把销售权、货权或结算方式强行统一。

三个路径有独立原创新画面：门店里买家试戴，工作室里创作者实测，社群空间里成员围桌讨论。图不再通过同一素材裁切假装换场景。路径的三个动作、合作准备说明、相关具名入口同时变化。内容与社群资料量仍少，数量不足不能靠虚构名单补齐。

02–03围绕同一副无品牌AI眼镜，从品牌产品资料开始，到合作准备稿、伙伴安排、买家体验、品牌成交履约、结果复盘结束。每一步都有可见对象与实际工作产物，说明品牌、伙伴、联野和买家分别做什么。演示是预设情境，未连接实时AI、真实伙伴或交易系统。

## 动效与响应式

路径演示：眼镜标记在“了解产品→体验/提问→品牌承接”间移动，同时更新行动说明；可手动点步骤，可停止。

六步故事：桌面合作台随滚动保留在视野内，右侧短叙事推进状态；按钮和播放也能导航。手动选择不会被自动观察器抢走，用户重新滚动时恢复滚动驱动。播放每4.2秒推进，末步自动停止；离开页面或演示区域时停止。工作资料出现、体验邀请与成交服务连线使用克制动效。

390手机：三列路径导航，完整场景图，形式和说明在图下；通路两列。六步导航为3×2，当前故事独立呈现。合作准备稿改为资料→准备稿上下排版；伙伴安排也增加高度。不是缩小桌面整幅图。320、390、768、1024、1440检查了代表性复杂状态。

减少动态效果开启时，播放关闭、动画停止，仍可逐步操作。无脚本时保留主要叙事、全部六步文字和通路资料链接。原生按钮、输入标签、状态提示、键盘焦点与跳转主要内容链接保留。

## 中文叙事顺序

1. 好产品，不该输在渠道上。走出Demo，走到会买的人面前。
2. 新品的下一站，可以是一整个销售世界。门店、内容、共同需求的人群各自解释。
3. 一款新品，一次一起做成的生意。不是抽象能力清单，而是同一款产品的一次合作。
4. 产品事实 → 合作准备稿 → 伙伴与形式 → 买家体验 → 品牌承接 → 真实结果决定下一步。
5. 给品牌：把产品带到买家面前。给伙伴：让受众与场景带来新品经营机会。联野推进合作并按真实服务和贡献收费。
6. 从一款产品、一个场景开始。邮件打开用户邮件应用，提纲复制到本机；没有假提交。

## 仍待现实验证

品牌付费意愿、任何主体的准入与合作条款、真实首销与退款表现、AI节约的实际时间/成本、归因与服务费模型、跨场景复用和可复制增长。公开资料中有主体或场景，不代表联野有权调用这些主体、受众和销量。社群入口不是销售许可。

## 设计稿与实现的关系

`design/state-storyboard.md`、三个路径稿、六个合作状态稿与手机总览先于实现完成。最终浏览器稿在其基础上调整：手机资料稿改上下排版，体验画面随所选伙伴联动，合作条款与复盘用真实HTML文字呈现。设计稿中“买家体验”固定社群图，成品扩展成三种伙伴对应画面。桌面改为连续叙事加固定工作台，没有照搬设计板的整页横向摆放。

设计稿不是像素锁定母版；这些差异已明确记录，不能声称成品与初稿逐像素一致。商业含义与视觉系统保持一致，实际截图单独供审阅。审美是否达标仍由用户判断，不用截图数量或自评分代替。
