# Clay源码拆解与联野改造标准

2026-10-18。依据本次实际读取的公开页面及其加载资源，不是对Clay私有仓库、设计源文件或后端的审计。

## 受阻原因与重试结果

此前浏览器页面接口多次超时，原生操作也曾因当时的窗口状态停止；这些结果不足以证明Clay官网整体无法访问。直接把该通道的问题扩大为整个参考工作无法继续，判断过重。

本次实测：官网HTML返回200，约379KB；定位并读取9个公开脚本/样式资源，均返回200。抓取清单和哈希在source-manifest.json、source/downloaded-assets.json。只把代码当数据检查，没有在本机执行下载的站点脚本。

Chrome原生窗口本次可读取。实际点击TAM Sourcing后，页面说明切换为查找目标账户，图像对象变为筛选条件与公司/岗位表；公开页面记录在browser/tam-after-click.txt。由此补齐至少一次真实用例切换的证据。截图接口仅得到约300px宽的窗口预览，不能当作高清视觉审查。后续原生窗口切换后已停止该通道；浏览器标签页接口仍超时，部分视频报告无法播放。窗口切换到非任务页面后立即停止，未对无关页面进行后续操作或保存其内容。

结论：**公开代码可读取、代表性用例能实际操作；完整媒体动态与高清中后段视觉仍有核验限制。** 不能继续用“Clay无法访问”概括，也不能把本次结果写成全站动效已完整验收。

## 联野目前实际差在哪里

以下为对照当前7d837f8预览与源码的设计判断，不是Clay官方结论。

1. **艺术资产仍偏静态。** 联野有原创街区与三幅独立场景，但首屏基本是一幅画。当前代码里的对象移动没有达到完整场景动作的表现力。继续增加淡入或缓动曲线不会补出新的画面状态。
2. **工作画面仍偏文字。** 旅行记录的购买理由、伙伴适配和资料交接已比前版具体，但“合作准备稿”和“复盘”仍主要靠读小字。需要让产品、演示提纲、体验问题和品牌承接对象在画面中保留前后联系。
3. **六步之间切页感仍强。** 当前setStory主要隐藏/显示整块面板。上一份资料到下一步怎样被使用，还不够直观。对象应有去处，而不是每步清空重来。
4. **具名通路的丰富度没有转成经营图景。** 名称恢复了，但目前主要是一张目录。应该让专业门店、内容机构与社群的经营方式先在画面里成立，再让目录提供纵深。公开名字仍不能充当联野合作背书。
5. **手机虽已重排，信息取舍还可更明确。** 当前分状态可读，但文档、主图、说明之间的优先级还不够锐利。每步只保留一个视觉焦点、一个具体问题和一个产物。

## 下一轮应执行的标准

### 01：一条路径是一套小型销售场景

继续保留“零售门店、内容推荐、社群私域”与合作形式两层结构。

每条路径准备三个完整状态：谁拿到新品 → 怎样让买家了解/体验 → 什么交给品牌。人物、产品、工作资料和承接入口要一起改变。用原创新场景和代码图层实现，不使用Clay的机械装置、界面截图或客户logo。

具名列表与主场景同时响应路径选择；目录保留来源与母体关系。薄弱类别按证据展示，不能为了视觉饱满编造名单。

### 02–03：让同一份资料沿合作过程被使用

继续使用明确标示的旅行记录眼镜假设。产品资料进入准备稿，适配理由进入伙伴安排，体验任务产生待记录问题，购买意愿交给品牌，真实结果留待复盘。

六个步骤仍保留；每个步骤要明确：上一状态留下什么、当前谁做什么、下一状态得到什么。场景切换时保留产品或资料的位置联系。文案、图层、选中态和当前动作由同一状态控制，避免分别播放互不相关的动画。

“需求→路径理由→体验任务”必须一致。选择创作者后，准备稿和后续体验都应围绕实测与原片表达；选择社群则围绕共同体验与具体问题。当前版本已做到文字联动，下一轮需要把这种关系做成可见对象变化。

### 验收应看什么

- 静音看短录屏，也能说出人物、产品和资料发生了什么变化。
- 桌面与手机分别验收构图，手机图中的主要信息不依赖放大。
- 任一步都可手动查看和暂停；自动播放不抢走用户正在操作的内容。
- 预设资料只表示工作方式；没有真实项目数据时，不出现成功订单、转化率、自动匹配分数或AI执行结果。
- 相同状态下保存设计稿与浏览器稿，逐对象检查位置、比例、字体和动作；用差异记录判断还原程度。

本轮完成的是源码与交互参考核查，并形成改造标准。联野当前前台仍为7d837f8；没有凭本次阅读宣布新的视觉还原已完成。生产站保持原样。
