# Clay 全页结构与联野 V3 的对应设计

参考：[Clay官网](https://www.clay.com/)；[官方设计复盘](https://www.clay.com/blog/new-homepage-2026)；官网实际加载的[交互脚本](https://clay-webflow-dev.vercel.app/app.js)。代码缓存保存在前一轮研究目录，本轮复用并补看模块，不执行下载的第三方脚本。

| 页面任务 | 本次核查重点 | 在联野采用什么 |
|---|---|---|
| 导航与品牌 | 品牌菜单、链接、复制与反馈属于清楚的真实操作 | 简单导航、实际邮件、复制与下载，不添加没有后端的假入口 |
| 首屏 | 一句承诺与持续运行的主视觉建立系统概念 | 真实经营街区、不同新品进入三种场景、购买问题出现；删除原来难懂的浮动标签 |
| 证明区 | 客户标识、评价和成绩组成有内容的视觉结构 | 联野没有这些成绩。用有来源的市场图谱提供纵深，明确它不属于客户证明 |
| 七个用例 | 单个用例有具体任务、界面与结果对象，选中态、文案与图层共同变化 | 按购买前的不确定性拆成三类产品：实际互动、真实工作流、原始效果；不再用眼镜解释一切 |
| 建造入口 | 输入内容连接真实产品入口，而不是首页假装完成AI任务 | 真实可下载的合作讨论提纲与邮件沟通，不做假AI聊天 |
| 数据、Agent、编排、执行 | 五段能力媒体各解释一个输入、动作与输出；图像有明确分工 | 图谱帮助看经营者，产品场景解释购买理由，合作过程解释推进、承接与复盘。AI能力保持在实际可说明的辅助环节 |
| 团队工作 | 业务能力落到具体人的工作，而不是停留在系统口号 | 分开说明品牌、联野、销售伙伴和买家的责任 |
| 客户故事 | 真实客户叙述与视频提供证明 | 不使用虚构故事、人物、订单、指标或评价补空白 |
| 学习与社区 | 不同内容形式让读者继续深入 | 图谱的二级经营分类、逐条业务档案与来源链接；丰富度来自信息深度 |
| 页尾 | 回到核心承诺与明确行动 | 回到具体产品和场景，以真实联系方式结束 |

以上是设计解释与取舍，不是声称联野已经达到Clay的艺术或商业完成度。没有复制其机械装置、UI图、客户logo或客户成绩。

## 动态核查依据

此前原站整页浏览器接口超时。本轮原站直接打开仍超时，但官方HTML、公开脚本与官方媒体可读取。建立了仅供本机研究的媒体索引：媒体仍从Clay官方地址加载。浏览器实际读到9段媒体readyState为4；主视觉有播放时间变化。另保存五段能力章节的画面，并结合源码检查rotate、logos、company、customer、background-video、sculptor等模块。该索引没有复刻原站全部交互，因此不能当作原站全交互验收。

源码所见的关键方式：预制主视觉视频；用例的多图层与独立手机图；统一状态、错开过渡与手动接管；按视口处理媒体；具体工作展示、客户证明和资源内容交替。联野借用这些组织原则，而不是只增加缓动或任意漂浮。

## 本轮仍保留的技术边界

联野人物与建筑是六幅新生成素材中的静态绘图；真实动态来自产品、界面素材、问题、连接线与角色交接，默认运行并可暂停。没有制作Clay式人物动作视频，也没有实时3D场景、AI推理或交易系统。源码阅读无法代替这些独立生产工作，交付不宣称它们已经具备。
