# V2.2 设计与叙事说明

本轮从V2.1独立建立，没有覆盖对照版本。核心变化是让产品、资料与承接关系留在同一个画面，减少整块面板轮流替换。

视觉语言沿用奶油白、深绿、朱红、浅鼠尾草绿，系统中文字体；大场景、产品实体和轻量工作物构成主要层次。桌面主标题约64px、场景标题约36px；手机主标题34px，场景及合作主句23–29px。正文13–18px，来源与示意说明独立降低层级。交互选中态同时使用文字、下划线与aria-pressed，不只依赖颜色。

## 全站叙事

1. 好产品，不该输在渠道上。新品应走到会买的人面前。
2. 门店：试戴、尝试操作、看原片。内容：真实使用、原片表达、适用与限制。社群：共同需求、小范围体验、具体问题。三条路径先呈现场景，之后才展开具名参考入口。
3. 一次合作：带上新品 → 准备合作 → 对接伙伴 → 买家体验 → 品牌承接 → 结果复盘。演示始终围绕“想记录旅行，又不想频繁举手机”的需求假设。
4. 品牌带来产品与履约能力，伙伴带来内容、受众或空间；联野推进材料、条件、协作与复盘。费用基于实际服务和约定贡献。
5. 真实邮件入口与可复制、可下载的沟通提纲。

## 两个重新实现的模块

01：三幅独立原创建图保留。产品样机进入场景；第二幕出现实际体验问题；第三幕交给品牌。对应标题、工作物、来源角色、下一步、具名通路与合作形式同步。所有状态由同一应用状态驱动，可暂停、逐步选择、键盘切换。

02–03：品牌资料与品牌承接位置始终在场。眼镜是同一DOM对象；准备稿展开为体验问题与三项任务；进入伙伴场景后，资料继续用于组织体验；购买意愿连接品牌服务；最后出现等待真实记录的复盘观察项。没有生成成功订单或假数据。选择内容或社群，会同步更新路径理由、提纲、场景、伙伴贡献、体验问题与合作形式。

手机将左右结构改为上下结构；场景、产品、提纲分层，品牌承接放在底部或第五步展开；步骤栏可横向浏览，选中项自动保持可见。没有将整张桌面画面缩小塞进手机。

## 从设计稿到浏览器

开发前保存9张1440×1000状态构图和390宽手机构图。浏览器按1440和390逐状态检查。实际实现调整了共享资料的高度、产品位置、手机品牌区和流程线位置；图像来源、色彩、主体关系保持一致。设计稿是构图基准，不是像素完全一致的声明。

主场景仍是静态原创图像；动作来自前端产品、对话、资料和连接线图层。未制作Clay式人物动作视频或实时3D场景。阅读其公开代码后采用的是统一状态、分层过渡和独立手机构图方法，没有使用其品牌素材或客户证明。
